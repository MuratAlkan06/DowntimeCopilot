## S3 grounded policy answers, published guardrail, role checklists (2026-10-23)

- **Published guardrail.** `downtime-copilot-v1`, id `o8vfkguicck3`, published version `1` (us-east-1, created via CreateGuardrail + CreateGuardrailVersion). Denied topic: dosing or treatment advice not stated in the patient record or an existing provider order. Contextual grounding filter accepted by the installed botocore model and the region: GROUNDING 0.75, RELEVANCE 0.5. Both blocked messages are a clinically safe refusal that points to the provider's order, the medication record and the paper binder. `GUARDRAIL_ID` and `GUARDRAIL_VERSION` live in the local `.env` only (names in `.env.example`). With both set and `DRY_RUN=0`, `config.guardrail_mode()` is `bedrock`. Otherwise it falls back to the checker. `GUARDRAIL_MODE=checker` forces the checker. The earlier `sparthill-probe` DRAFT guardrail is unused.
- **Grounding needs a query (verified live).** ApplyGuardrail returns ValidationException when a grounding source is sent without a query. The adapter sends the grounding source only together with a query.
- **Packets and digest stay on the checker (deviation, verified live).** The denied topic cannot see the record, so it INTERVENED on packet and digest text that only restates a scheduled insulin dose from the snapshot. Record-grounded output without a query (packets, digest) therefore keeps the checker, which judges against the grounding source. That is the same path these used before S3. Policy answers (grounding + query) go through the published guardrail. Revisit if the owner wants the guardrail on packets, for example a packet-specific guardrail without the topic.
- **Refusal path.** A policy answer is replaced when no citation resolves to a parsed section with a verbatim quote, or when the guardrail intervenes. The replacement is the refusal ("I can't find this in the downtime policy." or the safety-check text) plus the 2-3 nearest sections. Nearest sections come from deterministic keyword overlap (title terms 3x, body-text sections only, ties in document order), with no extra model call. Each one is cited with its best-matching verbatim paragraph. `grounded=false`, `guardrail.reasons` say why, and the `PolicyAnswer` shape is unchanged.
- **Role checklists.** `app/checklists.py` is a deterministic parser with no model imports. Section 2 duty statements are split on `;` (or on commas when there is no `;`). Every numbered paragraph elsewhere that names the role (for example "charge nurse", case-sensitive "RN", "pharmacy", "unit clerk") is added, reduced to the sentences that name it. It is parsed once at startup and served by `GET /checklists?role=` (outside the frozen contracts, audited as `checklist.view`). Check marks stay in localStorage per role and outage.

## S4 paper form capture, crops and two-person verify (2026-10-23)

- **Owner deferral, restated.** Physical printed forms and real phone photos come later. The ≥80% field accuracy target on real photos stays parked. S4 acceptance runs on the seeded fixture images in `data/forms/fixtures/`.
- **Printable forms and fixtures.** One spec in `tools/form_fixtures.py` (`make forms`) writes, for `vitals_flowsheet`, `downtime_mar` and `admission_note`: a US Letter HTML template with print CSS, a layout map (`<form_type>.layout.json`: field → normalized `{x, y, w, h}`), and a seeded fixture photo with ground truth. The HTML places every box with the layout map's own percentages, so the map matches the print by construction. Field names are the `CapturedRecord` field schema per form type (`app/ai/forms.py` `MOCK_READS`). Fixtures use a handwriting font when one is installed (Noteworthy on macOS), otherwise the bundled Pillow font sheared to an italic. They add a slight rotation, noise and blur from a fixed seed. The vitals fixture has a scribbled-out pain score (ground truth `null`). The MAR fixture is heparin with a blank second verifier. Text outputs (HTML, layout maps, ground truth) regenerate byte-identical and are tested against git. Images are deterministic for a given Pillow and font, and the test regenerates them twice and compares. New dependency: `pillow` (Makefile `DEPS`), for fixture rendering and crop images.
- **Vision read.** `forms.read_form_with_boxes` sends the image to Nova 2 Lite (routing table `form_read`) with `prompts/form_read.md` v2. It returns fields, confidences, an `unreadable` list and optional per-field boxes. The live path runs only with `DRY_RUN=0`. Tests stub `app.ai.client._converse`, so CI never calls Nova.
- **Unreadable is never guessed.** A field the model returns as null, lists in `unreadable`, or writes as an illegibility token (`illegible`, `?`, `[unreadable]`, …) has value `None` and capped confidence. `none` is kept as data ("allergies: none"). `agreement.merge` clears the value on every `unreadable` flag. A read below 0.4 confidence is not used. Tests cover the live path (stubbed) and the DRY_RUN path.
- **Crops (contract-preserving).** `CapturedField.crop` stays the frozen contract's normalized box. The cropped image is a blob with a derivable ref, `crop:<record_id>:<field>`, served by the existing `GET /blobs/{ref}` (audited `blob.view`). It is stored beside the original image. Box choice per field: the model's box when it is valid (fractions or a 0..1000 grid) and its centre lands on the printed field (4% of the page as slack for tilt), else the layout map. Hallucinated boxes therefore cannot mis-crop a known template. The sources are audited per capture (`capture.crops`). DRY_RUN reads have no boxes, so dry runs crop from the layout map through the same code. An upload that cannot be decoded still captures, with boxes but no crop blobs.
- **Range flags.** Vital thresholds moved to `app/config.py` (`VITAL_RANGE_DEFAULTS`, overridable as `VITAL_RANGE_<FIELD>="low,high"`). Bounds are inclusive: exactly at a threshold is not flagged, anything beyond is flagged `out_of_range`. The same function feeds R-REC-02.
- **Review edits.** `PATCH /backload/{id}/fields/{name}` is allowed only while `needs_review` (409 after). It writes a `backload.edit` audit with before/after value and flag. Reader outputs stay untouched in `reads`, and the UI marks the field "Corrected by reviewer". An edited value gets confidence 1.0, and its flag is recomputed (`out_of_range`, or `unreadable` if cleared). An edit resets a pending first verification.
- **Two-person verify, enforced server-side.** A `downtime_mar` or `verbal_order` record whose `medication` is high-alert needs two `verify` calls by different people. High-alert means anticoagulant, opioid, insulin or potassium chloride (`drug_classes.is_high_alert`), and a test checks it against every seeded `high_alert` flag. The first call is held in the store's kv (`verify1:<record_id>`), the status stays `needs_review`, and the response carries `X-Verifications: 1/2`. A second call by the same actor is rejected with 409 and audited as `backload.verify_rejected`. Identity: two named verifiers (`verified_by`) are compared by name, so two RNs may double-check; otherwise they are compared by role (`X-Role`). The completing call sets `verified_by` to `"<first> + <second>"`, and both `backload.verify` events record role, step and required count. `GET /backload/{id}/verification` (outside the frozen contracts) drives the UI's "n of 2 verifications" banner and its prompt to the role switcher. `entered` still requires `verified`. The web client now sends `X-Role` on verify, edit and entered. Without real auth, identity is self-asserted, same as every role in this demo.
- **Textract on printed forms.** The Textract adapter still parses naive `Label: value` lines. Mapping its LINE blocks into the layout-map boxes is the follow-up that gives the second read on these forms. The live acceptance read ran with `TEXTRACT_ENABLED=0` to isolate the one Nova call.
- **Live read evidence (2026-10-23, us-east-1, `DRY_RUN=0`, `TEXTRACT_ENABLED=0`).** There was one Nova 2 Lite (`us.amazon.nova-2-lite-v1:0`) vision read of `vitals_flowsheet-01.jpg`. It used 592 input and 660 output tokens and took 3.2 s. Estimated cost: **$0.0018** at the `PRICING` table rates. 9 of 10 fields matched ground truth exactly. `time` was read as `03.30` vs `03:30`, and a reviewer edit fixes it. `pain_score` came back `null` and was flagged `unreadable` with no value. `spo2 = 89` was flagged `out_of_range`. Model boxes were accepted for `bed`, `time` and `initials`; the other seven crops came from the layout map. Sample of the structured output:
  `{"fields": {"bed": "12", "time": "03.30", "temp_c": "37.8", "heart_rate": "104", "resp_rate": "22", "bp_systolic": "148", "bp_diastolic": "86", "spo2": "89", "pain_score": null, "initials": "PN"}, "confidence": {"bed": 0.95, …, "pain_score": 0.0, "initials": 0.95}}`

## S5 demo mode and three-phase shell (2026-10-23)

- **P0 complete.** All three phases run end to end on the seeded demo, live (`DRY_RUN=0`) and in mock mode. The full three-phase design review is still pending.
- **`make demo`.** It runs `simulator.seed --fresh` (empties the app store), prints the URL, and opens a browser only with `DEMO_OPEN=1`. It never opens a window by default.
- **Offline replay of AI output (`web/sw.js`).** `GET /digest` was already kept by the network-first branch under its URL. `POST /policy/ask` cannot be a Cache API key (GET only). The service worker therefore stores each successful answer under a synthetic GET key, `/policy/ask?replay=<normalized question>` (trimmed, whitespace collapsed, lowercased), and keeps the newest 20. When the network is down, a question already asked on this device gets its recorded answer back, marked `x-dc-fallback`, and the UI says it is the recorded answer. A new question still gets the offline 503 and the binder message. "Simulate offline" never fetches, so `api.js` reads the same key itself (`policyReplayKey`). The two key functions must stay in step. Install now fetches the shell with `cache: 'reload'`, so a `VERSION` bump cannot install a stale file from the HTTP cache (seen during this slice). Shell `v10`.
- **Naming.** The phase tab stays "Go to downtime". The action button is "Declare downtime".
- **Mock MAR aligned with the fixture.** Both DRY_RUN MAR readers (`app/ai/forms.py`, `app/capture/textract.py`) return the fixture's heparin 5000 units SC. Crops therefore never contradict values, and the high-alert two-verify beat shows without an edit. A bed 12 MAR now fires R-REC-03 (inside heparin's window) instead of R-REC-01. Tests cover R-REC-01 with a MAR for a patient without a heparin order.
- **Snapshot time follows the server.** `noteSnapshot` accepts a backward move (a reseed rewinds the unit clock). It takes only live, unit-wide times: `/status` and the patient list, never one patient's packet (a stale patient's is older) or a cached copy.
- **X-Role on every write.** `api.js` adds `X-Role` from the role switcher to every non-GET request, so `capture.create` audits the real role. The server is unchanged.
- **Review rows.** A field's state follows its current flag. It is "corrected" when its value matches neither reader, or when the readers disagreed and the disagreement flag is gone. Counts and the Verify label recompute. After a save or verify, focus returns to the same control, or the next one that still applies. Field names use display labels (SpO2, BP systolic, Temp (°C), …).
- **Live evidence (2026-10-23, scratch stack, `DRY_RUN=0`).** 12 packets in 18.8 s, Bed 12 R-DUE-01 insulin, policy stat lab grounded (4.2.1-4.2.4, guardrail passed, $0.0131), vitals fixture read, typed heparin verbal order (R-VO-01, pharmacy group, 1 of 2), then offline and back online. Total spend $0.1993 (13 Sonnet 4.6 calls, 15 Nova 2 Lite calls). Live structuring left `provider_cosign` empty (shown unreadable) on the typed order. R-VO-01 still fired.
