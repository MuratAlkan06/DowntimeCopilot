## S4 paper form capture, crops and two-person verify (2026-10-23)

- **Owner deferral, restated.** Physical printed forms and real phone photos come later. The ≥80% field accuracy target on real photos stays parked. S4 acceptance runs on the seeded fixture images in `data/forms/fixtures/`.
- **Printable forms and fixtures.** One spec in `tools/form_fixtures.py` (`make forms`) writes, for `vitals_flowsheet`, `downtime_mar` and `admission_note`: a US Letter HTML template with print CSS, a layout map (`<form_type>.layout.json`: field → normalized `{x, y, w, h}`), and a seeded fixture photo with ground truth. The HTML places every box with the layout map's own percentages, so the map matches the print by construction. Field names are the `CapturedRecord` field schema per form type (`app/ai/forms.py` `MOCK_READS`). Fixtures use a handwriting font when one is installed (Noteworthy on macOS), otherwise the bundled Pillow font sheared to an italic. They add a slight rotation, noise and blur from a fixed seed. The vitals fixture has a scribbled-out pain score (ground truth `null`). The MAR fixture is heparin with a blank second verifier. Text outputs (HTML, layout maps, ground truth) regenerate byte-identical and are tested against git. Images are deterministic for a given Pillow and font, and the test regenerates them twice and compares. New dependency: `pillow` (Makefile `DEPS`), for fixture rendering and crop images.
- **Vision read.** `forms.read_form_with_boxes` sends the image to Nova 2 Lite (routing table `form_read`) with `prompts/form_read.md` v2. It returns fields, confidences, an `unreadable` list and optional per-field boxes. The live path runs only with `DRY_RUN=0`. Tests stub `app.ai.client._converse`, so CI never calls Nova.
- **Unreadable is never guessed.** A field the model returns as null, lists in `unreadable`, or writes as an illegibility token (`illegible`, `?`, `[unreadable]`, …) has value `None` and capped confidence. `none` is kept as data ("allergies: none"). `agreement.merge` clears the value on every `unreadable` flag. A read below 0.4 confidence is not used. Tests cover the live path (stubbed) and the DRY_RUN path.
- **Crops (contract-preserving).** `CapturedField.crop` stays the frozen contract's normalized box. The cropped image is a blob with a derivable ref, `crop:<record_id>:<field>`, served by the existing `GET /blobs/{ref}` (audited `blob.view`). It is stored beside the original image. Box choice per field: the model's box when it is valid (fractions or a 0..1000 grid) and its centre lands on the printed field (4% of the page as slack for tilt), else the layout map. Hallucinated boxes therefore cannot mis-crop a known template. The sources are audited per capture (`capture.crops`). DRY_RUN reads have no boxes, so dry runs crop from the layout map through the same code. An upload that cannot be decoded still captures, with boxes but no crop blobs.
- **Range flags.** Vital thresholds moved to `app/config.py` (`VITAL_RANGE_DEFAULTS`, overridable as `VITAL_RANGE_<FIELD>="low,high"`). Bounds are inclusive: exactly at a threshold is not flagged, anything beyond is flagged `out_of_range`. The same function feeds R-REC-02.
- **Review edits.** `PATCH /backload/{id}/fields/{name}` is allowed only while `needs_review` (409 after). It writes a `backload.edit` audit with before/after value and flag. Reader outputs stay untouched in `reads`, and the UI marks the field "Corrected by reviewer". An edited value gets confidence 1.0, and its flag is recomputed (`out_of_range`, or `unreadable` if cleared). An edit resets a pending first verification.
- **Two-person verify, enforced server-side.** A `downtime_mar` or `verbal_order` record whose `medication` is high-alert needs two `verify` calls by different people. High-alert means anticoagulant, opioid, insulin or potassium chloride (`drug_classes.is_high_alert`), and a test checks it against every seeded `high_alert` flag. The first call is held in the store's kv (`verify1:<record_id>`), the status stays `needs_review`, and the response carries `X-Verifications: 1/2`. A second call by the same actor is rejected with 409 and audited as `backload.verify_rejected`. Identity: two named verifiers (`verified_by`) are compared by name, so two RNs may double-check; otherwise they are compared by role (`X-Role`). The completing call sets `verified_by` to `"<first> + <second>"`, and both `backload.verify` events record role, step and required count. `GET /backload/{id}/verification` (outside the frozen contracts) drives the UI's "n of 2 verifications" banner and its prompt to the role switcher. `entered` still requires `verified`. The web client now sends `X-Role` on verify, edit and entered. Without real auth, identity is self-asserted, same as every role in this demo.
- **Textract on printed forms.** The Textract adapter still parses naive `Label: value` lines. Mapping its LINE blocks into the layout-map boxes is the follow-up that gives the second read on these forms. The live acceptance read ran with `TEXTRACT_ENABLED=0` to isolate the one Nova call.

It used 592 input and 660 output tokens and took 3.2 s. ## Unit-clock stamps shipped; wall-clock TODO retired (2026-10-24, S5 fix)
app/clock.py provides unit_now() (simulator time + monotonic elapsed, synced on every successful /clock read). Audit ts, cost ts, digest generated_at, and /status restored_at use it. The wall-clock UTC fallback applies to any process that has NEVER synced: the seed CLI, a fresh app before its first /clock read, or one whose simulator has been unreachable since start. A process that synced once stays on the unit clock if the simulator later goes away. The pull path (POST /snapshot/pull and the scheduler) now reads /clock before it writes the snapshot.pull audit row, so a fresh app's first pull is stamped in unit time; if that read fails, the pull still runs and the fallback applies. Store.audit takes the stamp under the store lock, so ts order matches seq order with parallel writers. Still wall-clock by design: pulls.pulled_at (internal bookkeeping) and the S3 audit object key (S10). The earlier "backend wall-clock vs sim-clock divergence" TODO is retired.

- **Changed-allergy restore delta.** The simulator restore adds a third deliberate change: a new documented allergy (cephalexin, rash, moderate) on one seeded patient. It is drawn with the same `SEED` rng after the order and transfer picks, so those picks are unchanged (default seed: DIFF-ORDER Bed 19, DIFF-ADT Bed 5 to ICU 4). The restore diff reports it as `DIFF-ALLERGY` (warning), for allergies added or removed, compared case-insensitively. Like DIFF-ADT and DIFF-ORDER, DIFF ids are diff findings, not README rules.
- **R-REC-04 and the README exception.** R-REC-04 (recovery, critical) fires when a downtime MAR dose differs from the ordered dose for the same medication. The owner authorized one exception to the frozen README: one row in the Rules table. `test_registry_is_exactly_the_readme_table` now checks that the table and the engine agree.
- **Unit-string decision (R-REC-04).** A dose must be a single fixed amount plus a unit, with an optional `/time` rate. Unit spellings are canonicalized (mg, milligram(s); units, unit, u, IU; mcg, µg, microgram(s); ...), and mass units are compared in mg. So `5 mg`, `5mg`, `5 milligrams` and `0.005 g` are the same dose and do not fire. The same number with a different dimension (`5 units` vs `5 mg`, `8 mg/h` vs `8 mg`) does fire. Not judged: doses that are not one fixed amount (`sliding scale`, `per DKA protocol`, `800-160 mg`), an unreadable paper dose (already flagged for review), and a medication with no order (that case is R-REC-01).
- **Planted set.** The DEMO.md scripted flow on the default seed yields exactly 6 discrepancies: R-REC-01 Bed 2, R-REC-02 Bed 12, R-VO-01 Bed 7, DIFF-ALLERGY Bed 16, DIFF-ORDER Bed 19, DIFF-ADT Bed 5. `test_scripted_flow_yields_exactly_the_planted_set` pins the set. The R-REC-01 case requires the MAR to be captured with Patient: Bed 2.
- **Digest provenance convention.** The digest uses only the patient roster, records with status verified or entered, open discrepancies that do not depend on an unverified record, and lifecycle audit events. A `needs_review` record adds no content, only the audit fact that it awaits verification. Its discrepancies are held back and counted. ShiftDigest is frozen, so provenance goes in each SBAR item's `source_path`: one or more refs, comma-separated, from `snapshot.<patient_id>.<field>`, `captured.<record_id>`, `discrepancy.<discrepancy_id>`, and `audit.<seq>` (store sequence, via `Store.audit_log()`). Every ref must resolve to a fact given to the model. Other lines are dropped, and a patient the model leaves out gets the deterministic SBAR. Prose uses display names (Bed 12, SpO2, RN). Prompt `digest.md` v2 asks for this, and `display()` enforces it on every line. It also strips refs from prose: live Sonnet appended them to open items. The checker guardrail checks the summary and open items. If the check does not pass, the deterministic summary is used. `digest.generate` audits the verdict.
- **Incident report filter rules.** `GET /incident` is outside the frozen contracts. It builds its timeline from an allowlist of lifecycle audit actions in store sequence order: `downtime.start` (plus a "packets generated" row), `capture.create`, `backload.edit`, `backload.verify`, `backload.verify_rejected`, `backload.entered`, `recovery.restore` (plus one row per stored discrepancy, latest restore only, severity order) and `recovery.restore_failed`. Excluded as noise: views and lists, `ai.call`, `rules.evaluate`, snapshot pulls, sync, and its own `incident.view`. The two-paragraph summary comes from Sonnet 4.6 (route `incident`, `prompts/incident.md` v1), written from the same rows. The checker guardrail checks it, with the deterministic text as fallback. In DRY_RUN the summary is canned. Print uses `body.printing-incident` and fits one letter page (14 rows checked).

## S7 offline queue, pre-cache and true-offline reload (2026-10-24)

- **IndexedDB queue (`web/js/queue.js`).** A capture that cannot reach the server is queued as the full submission: image Blob (stored as-is, no data URL), form type, patient, read-back text and the submitting role. The store interface is `put` (upsert by id), `list` (oldest first) and `delete`. `idbStore()` backs it with IndexedDB database `dc-queue`. `memoryStore()` is the test double and the fallback where IndexedDB is missing. The item's own role is sent as `X-Role` when it drains, not the role selected at drain time. The form clears once the item is stored, so the same paper is not queued twice.
- **Idempotency id.** `crypto.randomUUID()` is generated at submit and sent on the first attempt and on every retry as the `client_id` form field. `POST /capture` looks the id up first. A known id returns the record it already created with 200: no new record, blob or `capture.create` audit. A new id creates the record (201) and the audit details carry the id. The id is stored in a storage-only `captured.client_id` column with a unique index. It is added in place to stores created before S7. `save_record` keeps the id on later saves (verify, edit). `CapturedRecord` and the other contracts are unchanged. Nothing awaits between the lookup and the save, so a single-worker app cannot interleave two submissions of one id. The unique index is the backstop.
- **Single drain.** Every trigger calls one `drain()`. It is guarded by an in-flight flag in the page and, where supported, a Web Lock (`dc-capture-drain`, `ifAvailable`), so two tabs never drain at once. An item is deleted only after a 2xx. Any other failure keeps it for the next drain. An offline result stops the drain, because the rest would fail too.
- **Triggers.** Startup, the page's reconnect (the `online` event, a live response after a failed fetch, or "Go back online"), a 60 s interval and Background Sync. Background Sync is Chromium-only. The page registers tag `dc-capture-drain` when it queues. The service worker's `sync` handler only wakes the open pages, which own the queue, the lock and the UI. With no page open, the queue drains on the next start. Other browsers rely on the online event and the interval. A drain from the service worker itself (without a page open) is a follow-up: it would need either a module service worker or a second copy of the drain.
- **Migration.** On startup, a pre-S7 localStorage queue (`dc.pendingCaptures`, data URLs) moves into IndexedDB as Blobs, then the key is cleared. Ids are derived from position and queue time, so a run interrupted before the key is cleared does not duplicate items, and the server sees the same ids.
- **Pre-cache tolerance.** Declare downtime also fetches `/checklists?role=` for all four roles, alongside the packet pre-fetch, into the service-worker data cache. Each role is fetched on its own (`allSettled`), so one failure does not stop the rest. The checklist card reads the Cache API to say which roles are cached ("all 4 roles", or which ones are missing), so the line is still true after a reload.
- **Offline navigation.** Navigations are network-first. An online reload gets the current shell and refreshes the cached copy (scope root and `index.html` only). Offline, or on a server error, the cached shell is served with `ignoreSearch`, so `/?phase=during` reloads with no network. Activate already deletes every `dc-` cache of another version. Shell `v14`.
- **Connectivity signal.** A stale-while-revalidate packet hit (stamped, with no fallback mark) is a cached copy served without asking the network. It no longer clears the offline state. Before, it hid the *Cached copy* note on packets opened offline, and with the reconnect redraw it would have fired a reconnect on every cached packet.
- **Reconnect redraw.** When the page reconnects, it re-fetches the patient list, the open packet (in place, no spinner or scroll), the checklist and an open Recovery view, so cached notes clear without reopening anything (the S1 carry-over). A **N queued** badge next to the offline toggle counts down as items drain.
- **Evidence (2026-10-24, scratch stack, `DRY_RUN=1`, Chromium via Playwright, 375 px).** The network was cut by stopping the app server: the browser got connection-refused, a real fetch failure. Playwright here cannot toggle the browser's own offline mode, so `navigator.onLine` stayed true and Background Sync was not exercised. The run: declare downtime, then 12 packets and 4 checklists in the data cache, then server stopped, then reload. The shell, 12 patients, rule badges (R-ALG-01, R-DUE-01, R-DUP-01, R-STALE-01), the Bed 12 packet with *Cached copy* and the checklists for all 4 roles all rendered. Then 2 captures were queued in IndexedDB (vitals fixture Blob, 91,690 bytes; typed verbal order), the page was reloaded again offline (queue still 2), and the server was restarted. The queue drained 2 to 0 with no action, giving one record and one `capture.create` per client id (3 `POST /capture` in the app log for 3 items, including one migrated legacy entry). ## S8 Textract AnalyzeDocument second reader (2026-10-24)

- **Call.** The Textract read is now `AnalyzeDocument` with `FeatureTypes` `FORMS` and `QUERIES`, checked against the installed botocore model. It replaces the naive `Label: value` parse of `DetectDocumentText` lines (the S4 follow-up). There is one query per layout-map field. The query text is a natural question (ASCII only, because the `QueryInput` pattern rejects the degree sign) and the `Alias` is the field name. `HumanLoopConfig` is never sent, so no human review loop sees a patient form, and a test checks the call kwargs.
- **Query cap and priority.** At most 15 queries per page (the synchronous AnalyzeDocument quota). No current template has more than 10 fields. When a template has more, `textract.PRIORITY` decides: medication, dose and route; then vitals (SpO2, resp rate, heart rate, BP, temp, pain); then allergies; then bed and times; then weight, height and history; then the admin sign-offs (second verifier, initials). Unknown fields come last. A field without a query can still be mapped from the FORMS key-values.
- **Mapping.** A `QUERY_RESULT` found by alias wins (the highest-confidence answer). Otherwise a `KEY_VALUE_SET` key is matched to the field by fuzzy label (difflib ratio, or every word of the field label in the key, threshold 0.8, one key per field). Any other template field is `None` at confidence 0. Confidence goes from 0..100 to 0..1, clamped.
- **Crop source.** A Textract answer's normalized `BoundingBox` is the first crop source when its centre lands on the printed field. Then the vision model's box, then the layout map. `capture.crops` audits the source as `textract`, `model` or `layout`.
- **AccessDenied.** `AccessDeniedException` / `AccessDenied` is caught explicitly. It is logged once, and Textract is skipped for the rest of the process. The record has no Textract read, so every field is `single`. There is no retry. Other client errors still raise.
- **Evals hook.** `evals.run.score_reads` scores `reads.textract` and `reads.bedrock` separately against ground truth, plus the merged record and the agree / disagree / single split. A reader that did not run scores `None`. S11 owns the full harness.
