# Contributing

## Working rules

- Branch per role, PRs into `main`, Role 3 merges. `main` always runs `make demo`.
- Contracts (`contracts/`) are frozen at 7:30 PM. Changing one means a PR that touches every consumer, re-runs `make schemas`, and a message to the team.
- Any item over 3 hours: stop, ship what meets the acceptance line, move to the next P.
- Credentials come by direct message only, live in `.env` (git-ignored), never in code, docs, or chat channels. `source .env` before running anything. When calls fail with `ExpiredToken`, fetch fresh keys; nobody debugs code.
- Everything that touches a model is logged (model, tokens, latency, estimated cost). `RESULTS.md` is generated by `make evals` and never hand-edited.

## Roles and directories

| # | Role | Owns |
|---|---|---|
| 1 | App & Experience | `web/` |
| 2 | Data, Snapshots & Rules | `simulator/`, `app/rules/`, `data/patients/` |
| 3 | Bedrock Intelligence (integrator) | `app/ai/`, `data/policy/` |
| 4 | Capture & Reconciliation | `app/capture/`, `data/forms/` |
| 5 | Platform, Sync, Evals & Demo | `tools/`, `app/sync/`, `evals/`, `DEMO.md`, `RESULTS.md` |

Work in P0 order across the team before anyone starts P2.

## Commits and PRs

- Conventional commits: `type(scope): subject`, lowercase subject, 72 characters or fewer, no trailing period.
- No AI-attribution trailers or lines (`Co-Authored-By: Claude`, "Generated with ...") in commits or PR bodies.
- Stage explicit paths only (`git add path/to/file`), never `git add -A`, `-u`, or `.`.
- Run `make guard` (`bash tools/guard.sh`) and `make test` before every commit.

## The probe and secrets

- `tools/bedrock_probe.py` is distributed by DM and is git-ignored. `tools/guard.sh` fails if it is ever tracked.
- `docs/probe-results.md` must stay redacted: no account IDs, no ARN account segments. The guard enforces this.
- Fallback decisions per service are in `docs/decisions.md`.
